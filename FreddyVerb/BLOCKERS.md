# Blockers and workarounds

Things that could not be done as specified in this environment, what was done instead, and how to finish them.

| # | Item | Status | Workaround / how to finish |
|---|------|--------|----------------------------|
| 1 | **AAX format** | Skipped | The AAX SDK is not public. Pass `-DFV_AAX_SDK_PATH=/path/to/aax-sdk` to CMake and the AAX target is added automatically (`juce_set_aax_sdk_path`). Signing (PACE wraptool) is also required for Pro Tools release builds. |
| 2 | **macOS / Windows builds verified locally** | Not possible here | Development runs on Linux (VST3, CLAP, LV2, Standalone are built and validated here). macOS Universal (AU/VST3/CLAP/Standalone) and Windows x64 are built and tested by `.github/workflows/ci.yml`. The vDSP FFT backend is compiled only on macOS, so it is exercised by CI, not locally. |
| 3 | **pluginval release binaries** | Downloads blocked (HTTP 403 through the session proxy) | Built pluginval v1.0.4 from source (`/home/user/deps/pluginval`). CI downloads the official release binaries. |
| 4 | **Blender (photoreal skins)** | Not installed | `tools/panel_forge` uses the procedural Python pipeline (numpy/Pillow/scipy) as the spec allows; see DECISIONS.md. |
| 5 | **JUCE licence page (juce.com)** | Host not reachable from this session | README licence notes are based on the repository's LICENSE.md plus the published JUCE 8 tiers as known at writing time. **Re-check https://juce.com/legal/juce-8-licence/ before release.** |
| 6 | **Intel IPP FFT backend** | Not implemented | `FV_USE_IPP` is wired in CMake but the convolver ships with PFFFT (double, AVX) on Windows/Linux, which the spec allows ("Intel IPP or PFFFT"). |
| 7 | **pluginval `--randomise` state test on 2-option choices** | Known JUCE/VST3 artefact, not fixable plugin-side | In random test order pluginval fuzzes parameters before the state test. JUCE's VST3 wrapper caches the host's raw normalised value (e.g. 0.304) for a 2-option choice (Quality), while the parameter itself snaps to 0 or 1. The state test compares against that stale cache, so it can fail by up to 0.5 on Quality. A real bug this mode exposed — bool/choice parameters not re-syncing after `setStateInformation` — **is fixed** (explicit re-push after `replaceState`, with a unit test). The standard fixed-order pluginval run at strictness 10 (used by CI) passes. |
| 8 | **One unexplained pluginval crash (exit 139)** | Not reproduced | One crash (segfault) in the first M6 run, which ran right after a full rebuild under heavy machine load. 30+ later runs (incl. 24 randomised repeats under gdb) showed no crash. Keep watching CI; if it recurs, the gdb command in PROGRESS.md (M6) captures a backtrace. |
| 9 | **CLAP validation locally** | Not run here | pluginval can't load CLAP and building `clap-validator` from source was not permitted in this session. The CLAP target builds, and CI now runs the official `clap-validator` release on Linux. |
| 10 | **Installers, signing, notarisation** | Scripts only | `packaging/macos/build_pkg.sh` (pkgbuild/productbuild, optional Developer ID signing) and `packaging/windows/FreddyVerb.iss` (Inno Setup) are built by CI on macOS/Windows; they cannot run on this Linux machine. Apple notarisation (`notarytool`) and Windows Authenticode signing need your certificates and are not configured. |
